# Bloom

Русскоязычный сайт-презентация будущего приложения: фирменная композиция BLOOM, контекст выбора, путь к объяснению, оригинальные экраны Keynote и прозрачность источников.

## Запуск

Требуется Go 1.22+. Из bloom-site/:

```sh
go run .
```

Откройте http://localhost:8080. Другой порт: `PORT=8090 go run .`.

## Сборка и проверка

```sh
go test ./...
go vet ./...
node --check static/js/app.js
npm run build
```

`npm run build` создаёт dist/index.html и dist/static/. Тот же HTML обслуживает Go-сервер. React-scaffold сохранён отдельно. `npm run lint` проверяет и scaffold; целевая проверка сайта: `./node_modules/.bin/oxlint static/js/app.js scripts/build.mjs`.

## Что редактировать

- templates/index.html: русский текст, последовательность разделов, подписи, SEO, изображения и магазины.
- static/css/style.css: утверждённые цвета, Onest, адаптивность и фокус.
- static/js/app.js: вступление и ScrollTrigger. Колесо, касания и клавиатура управляют естественной прокруткой.
- static/images/: опубликованные WebP и социальное превью bloom-social.jpg.
- assets/keynote-originals/: извлечённые оригиналы Keynote с исходным качеством; в dist/ эта папка не включается.
- static/fonts/: локальные WOFF2, исходные TTF и OFL.txt.
- PRODUCT.md: подтверждённое позиционирование и ограничения.
- DESIGN.md и docs/DIRECTION.md: визуальная система, концепция и референсы.
- docs/VERIFICATION.md: проверки, очистка и ограничения.

При замене изображения сохраняйте его пропорции и обновляйте width, height и alt. Фотографии из презентации служат иллюстрациями. Рейтинг, значения и экраны показывают концепцию будущего приложения. Методика оценки требует проверки перед запуском.

## Ссылки магазинов

В конце HTML находятся две кнопки с data-store="app-store" и data-store="google-play", aria-disabled="true" и видимой подписью «Скоро». После получения проверенных ссылок замените соответствующий button на a, добавьте href, удалите aria-disabled и обновите статус. Шаблон:

```html
<a class="store" data-store="app-store" href="ПРОВЕРЕННАЯ_ССЫЛКА">
  <span>App Store</span><small>Открыть</small>
</a>
```

## Материалы для публикации

Реальные ссылки на приложение, утверждённая методика оценки, подтверждённые исследования/нормативы/протоколы с применимостью к образцам, финальные юридические сведения владельца и контакт. После выбора публичного домена задайте абсолютный og:image и canonical. Уточните права на исходные изображения и брендовые материалы. Для вступления используется предоставленный Blender-исходник bloom-intro-v4/Bloom-Intro.blend. Права на него и брендовые материалы должны быть подтверждены владельцем перед публикацией.

Сайт работает автономно: локальные библиотеки и шрифты, статичный читаемый HTML. `prefers-reduced-motion` показывает готовую композицию. При отключённом JavaScript сохраняются текст, навигация, изображения и заглушки магазинов.

## Blender-вступление

Трёхсекундная авторская анимация берётся из `../bloom-intro-v4/Bloom-Intro.blend`: лист собирается в знак на кадрах1–36, надпись появляется на37–77, финальная композиция удерживается на78–90. Веб-ролик `static/media/bloom-intro.mp4` запускается при открытии страницы. Исходная сцена сохраняется целиком; сайт использует готовые кадры её рендера. Видео без звука, с `playsinline`, без повтора. После завершения показывается идентичный финальный WebP-кадр. При reduced motion и отключённом JS сразу видна финальная композиция. Ошибка медиа сохраняет статичный логотип и диагностическое сообщение в консоли; запрет autoplay показывает статичный логотип.

Для обновления рендера нужны Blender, ffmpeg и cwebp. Путь к Blender можно задать через BLOOM_BLENDER_BIN. Из папки сайта выполните:

```bash
bash scripts/prepare-intro.sh ../bloom-intro-v4
npm run build
```

Скрипт сохраняет полный диапазон движения листа в кадре1320×800, подготавливает MP4 из исходных PNG и два прозрачных WebP из отдельных RGBA-рендеров той же сцены. Папка-источник должна содержать `frames/0001.png`–`0090.png` и `Bloom-Final.png`. Параметры и происхождение: `assets/intro-blender/README.md`. Проверка запуска и fallback: `node --test tests/intro.test.mjs`.

## Прокрутка

Прокрутка нативная и непрерывная. Только при пересечении входа во второй слайд выполняется плавная остановка; следующий жест продолжает обычную прокрутку. С третьего слайда до конца wheel не блокируется. Обратное движение сразу отменяет подъезд. Touch, клавиатура и reduced motion сохраняют нативную прокрутку. CSS scroll-snap и GSAP/ScrollTrigger не используются. Переходы к фотоглавам доступны обычными ссылками. Вторая сцена использует context-packaged-wide.webp; её оригинал и описание генерации хранятся в assets/generated/.
